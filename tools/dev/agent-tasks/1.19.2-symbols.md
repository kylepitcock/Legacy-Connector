# 1.19.2 symbols: top 300 unresolved Minecraft/Forge symbols of the sample

Machine-readable list for [Legacy 1.19.2 estimate](../../../docs/wiki/Legacy-1.19.2-Estimate.md) (2026-11-16). Scoping only, no 1.19.2 support code exists.

How it was made (all offline, nothing started): 451 Forge 1.19.2 jars (Modrinth, 400 most downloaded content mods plus their required dependencies, not committed) went through
the loader's `Forge1201Transformer` as if they were 1.20.1 jars (`./gradlew gap1201 -Pgap.translate=true`, the layer as it is today), then every reference was resolved against
Minecraft 1.21.1 + NeoForge + the other jars of the sample. What remained was classified by `tools/compat/gap1192_analyze.py` against `tools/dev/mc_member_diff.py` (the
Mojang-named 1.19.2 and 1.20.1 class/member lists joined by the stable SRG ids). SRG ids that are named only in the 1.19.2 table were named through it (opt-in
`./gradlew :loader:genSrgMojang1192 -Pexperimental.mc1192=true`). Symbols are written with 1.20.1 names; `jars` = number of sample jars that reference the symbol.

Classes:
- `a` a mechanical rename/move/table row between 1.19.2 and 1.20.1 fixes it (SRG ids that 1.20.1 names with the plain Mojang name, renamed or moved members and classes);
- `b` the API changed shape or was removed after 1.19.2 (1.19.3 to 1.20.1): needs an adapter, a rewrite or a stand-in;
- `c` the symbol is still there, unchanged, in 1.20.1: the 1.20.1 layer lacks it too (overlap with `1.20.1-symbols-leftovers.md`), not 1.19.2 work;
- `F` Forge API (Forge 43 to 47 and Forge to NeoForge), not diffed in this scoping (needs the Forge jars); `u` a member of a class that exists in both versions but is in neither list (synthesised by the layer or not mapped); `n` not a Minecraft member.
