# 1.2.5 shim requests (from worker A, loader side, to worker B, shim side)

Source: the real `ModLoader 1.2.5.zip` (MCArchive, 2012-04-02) read with `javap -p`; class names in the signatures are translated from 1.2.5 client notch names to the
1.4.7 names through the Calamus+Feather join (`./gradlew :loader:genMappings125`). The member names are real. A mod links against 1.2.5 notch names;
`Notch125To147` renames them to 1.4.7 names, which `ForwardRedirects` then maps to the 1.7.10 shim.

## Findings that change the plan

- **The 1.2.5 `ModLoader` statics and `BaseMod` hooks are already lower case** (`addName`, `registerBlock`, `onTickInGame(float, Minecraft)`, ...), exactly the 1.4.7 spelling.
  The capitalised form (`AddName`, `OnTickInGame(Minecraft)`) is the Beta spelling only. So the 1.4.7/1.6.4 `BaseMod`/`ModLoader` shim is nearly the right target, no capitalised facade.
- ModLoader 1.2.5 already carries a packet-250 model (`registerPacketChannel`, `sendPacket`, `receiveCustomPacket(Packet250CustomPayload)`, `serverChat`,
  `receiveChatPacket(String)`), not packet 230.
- ModLoader 1.2.5 is a jar mod: the zip holds `ModLoader`, `BaseMod`, `MLProp`, `ModTextureStatic`, `ModTextureAnimation`, `EntityRendererProxy` (unobfuscated names) plus 13 modified
  game classes (per the join: NetClientHandler adl, TileEntityFurnace ahg, RenderManager ahu, GenLayerBiome ahy, SlotFurnace ajv, WorldProvider alb, BlockDispenser alj,
  SlotCrafting amn, EntityItem fq, RenderBlocks vl, WorldType vx, and ko, uu). A mod jar never needs these; the layer drops them.
- Public statics of 1.2.5 `ModLoader` that the 1.6.4 shim `ModLoader` lacks:
  `addAchievementDesc(Achievement, String, String)`, `addAllFuel(int,int)`, `addAllRenderers(Map)`, `dispenseEntity(World,double,double,double,int,int,ItemStack)`,
  `loadImage(RenderEngine, String)`, `onTick(float, Minecraft)`, `openGUI(EntityPlayer, GuiScreen)`, `populateChunk(IChunkProvider,int,int,World)`, `receivePacket(Packet250CustomPayload)`,
  `registerAllKeys(KeyBinding[])`, `registerAllTextureOverrides(RenderEngine)`, `removeBiome(BiomeGenBase)`, `renderBlockIsItemFull3D(int)`, `renderInvBlock`, `renderWorldBlock`,
  `sendPacket(Packet)`, `serverChat(String)`, `serverConnect(NetClientHandler, Packet1Login)`, `serverDisconnect()`; fields `DEBUG`, `VERSION`, `props`, `cfgLoggingLevel`.
  The 1.6.4 shim has instead (not in 1.2.5, harmless): `addCommand`, `addEntityTracker`, `addTrade`, `clientSendPacket`, `getMinecraftServerInstance`, `registerContainerID`.
- `BaseMod` 1.2.5 members the 1.6.4 shim `BaseMod` lacks: `dispenseEntity(World,double,double,double,int,int,ItemStack)`, `receiveChatPacket(String)`,
  `receiveCustomPacket(Packet250CustomPayload)`, `serverConnect(NetClientHandler)`, `serverDisconnect()`.
- Overloads: `addSpawn` exists as `Class`/`String` x with/without `BiomeGenBase...`; `registerTileEntity(Class,String,TileEntitySpecialRenderer)`; `addName(Object,String,String)` (locale);
  `addOverride(String,String)` returns `int`, `addOverride(String,String,int)` is void; `addLocalization(String,String,String)`.

## Forge and FML in the corpus (second batch, measured on `forge-1.2.5-3.3.7.135-{client,server}.zip` and 37 mod units)

- **The Forge 3.x package is the top-level `forge`** (`forge/MinecraftForge`, `forge/ITextureProvider`, `forge/IGuiHandler`, `forge/IOreHandler`, `forge/ISidedInventory`, `forge/Configuration`, `forge/Property`,
  `forge/NetworkMod`, `forge/IConnectionHandler`, `forge/IPacketHandler`, `forge/MinecraftForgeClient`, `forge/ForgeHooks`, `forge/DimensionManager`, `forge/MessageManager`, `forge/EnumHelper`,
  `forge/oredict/{OreDictionary,ShapedOreRecipe,ShapelessOreRecipe}`, `forge/packets/*`), NOT `net/minecraft/src/forge`. Most used by the corpus: ITextureProvider (24 units), Configuration (20), NetworkMod (16),
  MinecraftForge (15), IConnectionHandler (14), MinecraftForgeClient (13), Property (11), ForgeHooks (10), IGuiHandler (9), ISidedInventory (8), IPacketHandler (8), DimensionManager (7).
- **Forge 3.3.7.135 for 1.2.5 bundles FML 2.2.48** (`cpw/mods/fml/{client,common,common/modloader,common/registry,server}`, `@Mod` with `Mod$PreInit/Init/PostInit`, `ITickHandler`, `IWorldGenerator`,
  `FMLCommonHandler`, `Loader`, `ModLoaderModContainer`, `SidedProxy`, `ServerRegistry`): Forge replaces ModLoader's default-package `ModLoader`/`BaseMod` by FML's reimplementation (same public API;
  FML's `BaseMod` also implements `cpw.mods.fml.common.modloader.BaseMod` and adds `onPacket250Received`, `onChatMessageReceived(EntityPlayer, Packet3Chat)`, `onServerCommand`, `onClientLogin`,
  `onClientLogout`, `onClientDimensionChanged`, `keyBindingEvent`; FML `ModLoader` adds `getMinecraftServerInstance()`, `isChannelActive(EntityPlayer,String)`, `serverLogin(NetClientHandler,Packet1Login)`
  instead of `serverConnect`). Corpus mods that touch `cpw/mods/fml`: IC2 1.103 (client+server), Forestry (client+server), PortalGun, LogisticsPipes (optional compat); all others are plain ModLoader + `forge/*`.
- **Server build API**: `ModLoader`/`BaseMod` of the server jar have the same names, but client types become `Object` (`getMinecraftInstance(): Object`, `onTick(float, Object)`), `BaseMod.onTickInGame(MinecraftServer)`
  (boolean) replaces the client `onTickInGame(float, Minecraft)`, and `getMinecraftServerInstance(): net.minecraft.server.MinecraftServer` exists.
- Two kinds of build are NOT notch-named: CraftBukkit/MCPC builds (`*_bukkit.zip`, `net/minecraft/server/mod_X`, MCP-style names, Bukkit refs): 6 units; ModLoaderMP `BaseModMp`/`ModLoaderMp`/
  `Packet230ModLoader` are used by 11 units (Backpack, MagicWands, ElementalCreepers server, MorePistons, SmartMoving, SDKs); the ModLoaderMP member tables are at the end of this file.

Source for the Forge 3.x API (MCP names, 504 files, includes forge/*.java and FML): `test-mods-mcarchive/1.2.5/forge-1.2.5-3.3.7.135-src.zip` in the main checkout (read-only, gitignored).
