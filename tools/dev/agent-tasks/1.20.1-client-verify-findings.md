# 1.20.1 findings of the offline bytecode verifier (`checkLegacyMod`, BytecodeCheck)

Source: `tools/dev/verify/suites/atm9-1201-all.txt` (108 ATM 9 jars + ATM10 libraries), master 3808bfb61 + the verifier follow-ups, 2026-11-16.
22,801 classes, 157,263 methods analysed, 0 methods skipped. Reproduce: `./gradlew checkLegacyMod -q -PlegacyJar=<jars>`; the closing `verify:` block lists the groups.
Negative control (the known `ModelResourceLocation` defect): `-PmodelLocation1201=false` brings it back as one group, 3 sites in 3 jars (ChemLib, SuperMartijn642
core lib, Wireless Chargers); on master it is silent. What the verifier cannot see (runtime casts, registration order...) is in `docs/wiki/Development.md`.

Every group below is a real defect of the translated bytecode (no false positive remains on this set), but three of the four sit in mods or code paths with low
exposure. Order = suggested priority.

## 1. `ItemStack` passed where the shim `CapabilityProvider` is required: 1 site, AE2 (`appliedenergistics2-forge-15.4.9`)

`appeng/api/stacks/AEItemKey.serializeStackCaps(ItemStack)`: `MethodHandle.invokeExact((CapabilityProvider)stack)`. The translated descriptor says
`legacyconnector/v1_20_1/net/minecraftforge/common/capabilities/CapabilityProvider` (an abstract class), but a 1.21.1 `ItemStack` is not one (in 1.20.1 `ItemStack`
extended Forge's `CapabilityProvider<ItemStack>`). The JVM verifier rejects this when `AEItemKey` links, and AE2's whole item-key path depends on that class.
Fix idea: rewrite the signature-polymorphic call's descriptor like the other `CapabilityProvider` receivers (`ForgeApiRewrites1201.PROVIDER`), or replace the
reflective `serializeCaps` lookup (a `MethodHandle` onto `CapabilityProvider.serializeCaps`) by a helper that returns the attachments' serialized form. Confidence
medium-high: if AE2 starts in game without a VerifyError, find which runtime step makes `ItemStack` a `CapabilityProvider` and teach the verifier about it.

## 2. Class implements a game type that is no longer an interface: 1 class + 2 call sites, Integrated Tunnels (`IntegratedTunnels-1.20.1-1.9.0`)

`org/cyclops/integratedtunnels/core/ItemHandlerWorldEntityExportWrapper` implements `net.minecraft.core.dispenser.BlockSource` (an interface in 1.20.1, a record in
1.21.1): `IncompatibleClassChangeError` when the class loads, and `getEntity()` passes `this` as a `BlockSource` (2 sites). Needs a facade for `BlockSource`
(a mod-side implementation cannot be a record) or a rewrite of the wrapper's use; the mod has native 1.21 builds, so this is low priority.

## 3. `DifferenceIngredient` returned as `Ingredient`: 1 site, AE2 datagen (`appeng/datagen/providers/recipes/CraftingRecipes.tagExcept`)

NeoForge's `DifferenceIngredient` is an `ICustomIngredient`, not an `Ingredient`. Data-generation code, never loaded in game (the datagen emptier left this method);
fixing it means extending the datagen emptying to whole `*/datagen/*` classes that fail verification. Low priority.

## Not findings (checked, the tool must stay quiet)

- `TerraBlender` `TerrablenderOverworldBiomeBuilder` extends the game's final `OverworldBiomeBuilder`, and Mekanism's `$LegacyItemPredicate` extends the final
  `ItemPredicate`: both are opened by an access transformer (`public-f`), which the check reads (TerraBlender's own, the layer's own).
- Still open and invisible to a verifier: the runtime `ClassCastException` of a `ModelResourceLocation` cast to `ResourceLocation` out of a generic container
  (a `checkcast`, so the verifier accepts it). Find those with a list of the rewritten call sites that return a `ModelResourceLocation`-typed generic and add a
  conversion at the container access, or a debug build that routes `checkcast ResourceLocation` through a helper accepting both.

## Blind spots on this set

109 distinct unknown types (88 after the modern libraries of the set were read into the hierarchy): optional integrations of mods that are not in the set
(JEI, REI, Jade, Waila, The One Probe, CraftTweaker, ComputerCraft, Tetra, snakeyaml, jankson). A method touching only those still gets checked, but a
mismatch involving them is invisible.

## Other versions (not for the 1.20.1 client worker; found by the same run)

1.12.2 (110 jars of `1.12.2 test mods`, 37,215 classes): 3 groups, all in the synthesized LWJGL GLU classes, the 1.12.2 shim lacks `Disk`/`Cylinder`:
- `legacyconnector_synth...glu.Disk` is not assignable to the shim `Quadric` (1 site, ExtraBitManipulation `ClientEventHandler.renderEnvelopedShapes`): add `Disk`
  and `Cylinder` to `legacyconnector/v1_12_2/org/lwjgl/util/glu` extending `Quadric` (like `Sphere`).
- `GLUtessellatorCallback` is synthesized as a class while Thaumcraft's `CoreGLE$tessellCallBack` implements it (1 class + 6 call sites): the generator must make
  it an interface (same cause as the existing generator failure `DeobfuscationTransformer ... can not implement IClassNameTransformer`).
1.7.10 and the `mixed` suite (6,338 classes): 0 findings.
