# 1.2.5: what the shim worker (B) needs from the loader worker (A)

Written 2026-11-16 by the run-time worker after the first server runs of real 1.2.5 jars (`-Pmappings125`, `./gradlew runServerSubTest -PsubTestDir=run-sub125`).

## 1. Name unjoined members after Feather, not after the obfuscated letter

`Notch125To147.UNJOINED_PREFIX + name` gives `mcc125$b` for a method whose obfuscated name is `b`. The client and the server of 1.2.5 are obfuscated separately, so `Block.b(World,int,int,int,EntityPlayer)` on the client is another
letter on the server: a shim hook keyed by the letter serves one side only. The join table already has the Feather name of every 1.2.5 member (`Block.use`, `Item.useOn`, `BlockWithBlockEntity.createBlockEntity`,
`Slot.onItemRemoved`, ...). Please emit `mcc125$<feather name>` (add the arity or the descriptor hash when two overloads share a name). The shim worker then writes the adapters once:

- calls: rows of `forward/1.4.7/member-manual.tsv` (`R ... static ... Redirects125`), done for the members of section A of the link probe that are calls (font, chat, explosion, tooltip, ...), keyed by the **client letters today**
  (`mcc125$b` of `FontRenderer`, `mcc125$l` of `Minecraft`, ...): they have to be re-keyed when the names change; the list is in `Redirects125` and the tail of `member-manual.tsv`;
- overrides (the larger part, and the one that decides whether a content mod works): the game calls the 1.3+ shape of a method and never the 1.2.5 override a mod declares. Shim hooks needed, each a default method that
  the matching 1.7.10-shaped method calls when the mod class overrides it (`Block.getHardness(int)` is the first, done): `Block.use` (1.2.5 `onBlockActivated(world, x, y, z, player)`), `Item.useOn`
  (`onItemUse(stack, player, world, x, y, z, side)`), `BlockWithBlockEntity.createBlockEntity` (no-argument `getBlockEntity()`), `Block.onRemoved`, `Block.updateMetadataOnPlaced`, `Block.addCollisions`
  (`getCollidingBoundingBoxes`), `Slot.onItemRemoved`, `Container.onClickSlot` (shift flag), `PlayerEntity.pickUp`.

## 2. Things seen on the first server runs

- `portalgun1.2.5v3_server` was hosted as 1.7.10 (it touches `cpw/mods/fml`), failed with `forge/NetworkMod` missing; fixed by your `fml125Candidate` branch (merged into this branch, not re-run).
- `mods/1.2.5/*.zip` is not read by `checkLegacyMod`/the locator: the files must be `.jar` (the corpus archives are `.zip`). Probe tooling copies them as `.jar`; a user dropping a `.zip` into `mods/1.2.5/` gets nothing and no message.
- The mods write config next to the game (`magicwands.properties` ended up in the working directory of the run, outside `config/`): ModLoader mods used paths relative to the `.minecraft` folder, which is the run directory in
  the layer; nothing to fix, only noted.
