Not done, with the reason:

- **GuiContainer.renderLabels**: no longer a stub in any jar of the set (round 1's fallback plus the super-call rows link); nothing left to fix.
- **Request 3 (own short-named classes shadow game names)**: the cluster of `AnvilChunkLoaderPending.*`, `EntityMooshroom.preventEntitySpawning`, `Teleporter$PortalPosition.teleporterInstance`
  (CustomRecipes, 13 members) is not shadowing: `ModLoader.addRecipe` is called with `Laan;`, which is not 1.2.5's ItemStack (`amb`); the jar is most likely compiled against another 1.2.x obfuscation
  (like NEWTON, 1.2.3; not verified against that version's names), so its game references land on unrelated classes of 1.4.7. Not a defect of the layer; the jar cannot work. The other "garbage" members of Mystcraft, Tropicraft and Thaumcraft
  came from the same two causes that are fixed now (unresolved inheritance, FML base classes).
- **More Pistons textures**: confirmed again. The 14 PNGs the zip contains are the `addOverride("/terrain.png", ...)` tiles (all present); the blocks' `getTextureFile()` returns
  `/morePistons/blocks/block_textures.png`, a sheet the zip does not contain, so the original game draws its missing texture too. Nothing to fix in the layer.
- **ModLoaderMP**: the shim covers the API the 1.2.5 ModLoaderMP had (`BaseModMp` handlePacket x2, handleSendKey, handleLogin, handleGUI, handleTileEntityPacket, hasClientSide, onClientLogin/Logout;
  `ModLoaderMp` sendPacket/To/ToAll, sendKey, registerGUI, registerEntityTracker(Entry), registerNetClientHandlerEntity (both shapes), sendTileEntityPacket, sendChat*, getModInstance, log);
  no jar of the set references a member that is missing, and no gap was found by comparing the API; behaviour over a real connection stays unverified.
- Client world swap (`World.<init>(World, WorldProvider)`, `Minecraft.setWorld/usePortal`, `Teleporter.<init>()`, `WorldClient.<init>`, `removeEntities`), Smart Moving's player accessors: out of scope, as agreed.
- Single members whose behaviour could not be established from the Feather names or the mods' use (no guess made): `PlayerControllerMP.mcc125$h`, `MinecraftServer.mcc125$m_7569445`, `MapData.mcc125$ticks`,
  `BlockRail.hasPowerBit`, `RailLogic.*` (a class 1.7.10 does not have), `EntityAnimal.targetOutOfSight`, `FoodStats.onUpdate` (calling it again would double the hunger tick),
  `EntityPlayer.updateItemUse`, `ItemStack.interactWith` (needs the acting player), `EntityAIArrowAttack.<init>(EntityLiving, float, int, int)` (1.2.5's mob shoots itself, 1.4's goal needs `IRangedAttackMob`),
  `RenderBlocks.renderBlockFire`, `RenderLiving.loadDownloadableImageTexture`, `ChatLine`/`ContainerCreative`/`GuiFurnace`/`GuiDispenser` (classes the 1.7.10 shim does not have), `MapData.playersVisibleOnMap` (List in 1.2.5, Map in the shim).
- Left from the ranking below (round 1) unchanged: `Item.addCreativeItems`, `Block.getTileEntity` (the two other branches), `EntityLargeFireball` members were verified only by linking.
