# 1.20.1 run-time failures by suite (headless server, `tools/dev/verify.sh <suite>`)

Updated by the run-time stability worker. Jars: ATM 9 instance. One server at a time, JDK 21.

## Fixed (batch 1, 6182eeab1, transformer 70)
- AE2 (and everything on its early startup): `@At(target = "pkg/Owner.name(desc)")` of a mixin was not moved from Forge to NeoForge packages, so
  `EarlyStartupMixin` (Bootstrap.bootStrap after `GameData.vanillaSnapshot`) never applied and `AEConfig.instance()` stayed null.
- `Datagen1201` emptied any method calling a static member of a jar class in a package called `datagen` (AE2 `ConventionTags.dye` -> null tag keys).
- Rewritten call on a client-class receiver (`Minecraft.player.getAttributeValue`, receiver LocalPlayer, helper takes LivingEntity): verifier loaded
  LocalPlayer on a dedicated server (Iron's Spells). CHECKCAST inserted in `Mc1201Migration.castClientReceiver`.
- `IForgeRegistry.register` on a frozen NeoForge registry in a mod constructor (AE2 Insert Export Card menu type): queued for the RegisterEvent.

## Fixed (batch 3, transformer 75): subclass of the final NeoForge `ModConfig` (Mekanism `MekanismModConfig`, Ars Nouveau `ANModConfig`)
`ModConfigSubclass1201` moves such a class to the facade `LegacyModConfig` (holds type/spec/container/fileName; `addTo` = `ConfigTracker.registerConfig`, `wrapperOf`
maps the real config of a `ModConfigEvent` back so `instanceof MekanismModConfig` and `clearCache(event)` work). `getHandler()` overrides link against a facade
`ConfigFileTypeHandler` but have no effect: server configs of those two mods stay in the world's `serverconfig` folder, not the global config folder.
Also in this batch: `CopyNbtFunction` -> `CopyCustomDataFunction` class rename (Mekanism BlockPersonalStorage loot), `DeferredRegister.createOptional(ResourceKey, String)`,
method references that need an in-place constructor rule (`BucketItem::new`) go through a generated static method (`Mc1201Migration.trampoline`), static
`@SubscribeEvent` methods of an object registered as an instance (`busRegister`).

## atm9-1201-4 (suite file as committed fails; needs `lib curios-neoforge-9.5.1+1.21.1.jar` in it: Cataclysm)
- Structurize: `RuntimeException: You are trying to run old mod on much newer vanilla ... DataVersion` (Blueprint data version table; MineColonies family, MultiPiston depends on it). Has a native 1.21.1 build: skip.
- Mowzie's Mobs (and Mowzie's Cataclysm, which requires it): `VerifyError: Bad access to protected data in invokevirtual` in `GongBlock$GongPartBlock.onProjectileHit`
  (`otherState.getBlock().onProjectileHit(...)`). 1.21.1 made ~50 `BlockBehaviour` methods protected (onProjectileHit, neighborChanged, onRemove, getDrops, ...) that were public in 1.20.1.
  A blanket access transformer does not work (vanilla subclasses overriding as protected then fail to compile: MDG recompiles with the AT). Needs a loader pass: a call to one of
  those methods whose receiver is not the calling class (or a subclass of it) goes through a generated accessor (Mixin `@Invoker` interface on BlockBehaviour + cast), like
  `Mc1201Migration.castClientReceiver`. Class of defect, affects every mod that calls those on other blocks.
- L_Ender's Cataclysm (with Curios lib added): world generation worker dies with `IllegalClassLoadError: accessor mixin ...WorldGenRegionAccessor` and the server never finishes
  spawn preparation (900 s timeout). Mixin1201 dropped the accessor (`cache` is not a `List` field of 1.21.1's `WorldGenRegion`) but the mod code still uses the interface. Needs either a
  `WorldGenRegion` cache view mixin or the accessor kept as a loadable interface whose methods the mod survives; deep mixin into changed internals, recorded.
- Other suite members (21 mods) load. Data errors: Cataclysm stonecutting recipe naming a stair item that is not registered (1), tag `minecraft:placeable` references (1).
