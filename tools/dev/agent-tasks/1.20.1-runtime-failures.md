# 1.20.1 run-time failures by suite (headless server, `tools/dev/verify.sh <suite>`)

Updated by the run-time stability worker. Jars: ATM 9 instance. One server at a time, JDK 21.

## Fixed (batch 1, 6182eeab1, transformer 70)
- AE2 (and everything on its early startup): `@At(target = "pkg/Owner.name(desc)")` of a mixin was not moved from Forge to NeoForge packages, so
  `EarlyStartupMixin` (Bootstrap.bootStrap after `GameData.vanillaSnapshot`) never applied and `AEConfig.instance()` stayed null.
- `Datagen1201` emptied any method calling a static member of a jar class in a package called `datagen` (AE2 `ConventionTags.dye` -> null tag keys).
- Rewritten call on a client-class receiver (`Minecraft.player.getAttributeValue`, receiver LocalPlayer, helper takes LivingEntity): verifier loaded
  LocalPlayer on a dedicated server (Iron's Spells). CHECKCAST inserted in `Mc1201Migration.castClientReceiver`.
- `IForgeRegistry.register` on a frozen NeoForge registry in a mod constructor (AE2 Insert Export Card menu type): queued for the RegisterEvent.

## Open: subclass of the final NeoForge `ModConfig` (Mekanism `MekanismModConfig`, Ars Nouveau `ANModConfig`)
Error: `IncompatibleClassChangeError: class X cannot inherit from final class net.neoforged.fml.config.ModConfig` (mod construction, 2 mods in atm9-1201-1).

What they do (javap of the 1.20.1 jars):
- constructor `super(type, spec, container, fileName)` (Mekanism: `(ModContainer, IMekanismConfig)`, file name `"<dir>/" + getFileName()`; Ars: `(Type, IConfigSpec, ModContainer, String)`).
- override `getHandler()` returning a nested `ConfigFileTypeHandler` subclass (`reader(Path)`/`unload(Path, ModConfig)` redirect the SERVER config from
  `serverconfig` to the global config dir). `ConfigFileTypeHandler` does not exist in NeoForge 1.21.1 either.
- Mekanism: `MekanismConfigHelper.registerConfig` does `new MekanismModConfig(container, cfg)` then `container.addConfig(config)`; `Mekanism.onConfigLoad(ModConfigEvent)`
  does `event.getConfig() instanceof MekanismModConfig m -> m.clearCache(event)` (value caches reset on load/reload). Ars: only constructs, then `container.addConfig`.

Design option (not implemented, estimated 1.5-2 h incl. tests):
1. Facade `legacyconnector/v1_20_1/net/minecraftforge/fml/config/LegacyModConfig` (non-final, NOT a ModConfig): fields type/spec/container/fileName, delegating getType/getFileName/
   getSpec/getModId/getFullPath/getConfigData; empty `ConfigFileTypeHandler` facade (reader/unload no-ops) so the nested handler classes link.
2. Loader: a mod class whose super is `net/minecraftforge/fml/config/ModConfig` gets super `LegacyModConfig`; `ModContainer.addConfig(x)` on such a class becomes
   `LegacyModConfig.addTo(container, x)` = `container.registerConfig(type, spec, fileName)` (real ModConfig stored in a WeakHashMap real->wrapper) and a mod-bus listener
   for ModConfigEvent; `INSTANCEOF X` / `CHECKCAST X` of such classes go through `LegacyModConfig.wrapperOf(Object)` so `event.getConfig() instanceof MekanismModConfig`
   finds the wrapper.
3. Loss: the server config file location stays NeoForge's (`serverconfig` of the world), not the global config dir.
Cheaper partial option: only 1+2 without the instanceof rewrite (Mekanism then never clears its caches on reload; values stay as first read).
