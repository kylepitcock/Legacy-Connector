# Legacy 1.20.1: client events

Part of the 1.20.1 pipeline notes ([Legacy-1.20.1-Estimate](Legacy-1.20.1-Estimate.md), [Development](Development.md)). Audit of every Forge 47.x client event against NeoForge 1.21.1,
written 2026-11-16 after a 1.20.1 mod failed in a client with "net.neoforged.neoforge.client.event.TextureStitchEvent does not exist" (1.21.1 has `TextureAtlasStitchedEvent`).
Nothing was run in a game: the table comes from the class files of `forge-1.20.1-47.4.20-universal.jar` and NeoForge 21.1.258 (merged jar, bus, FML loader) and from the
layer's own tables.

## How the 1.20.1 pipeline maps events

* **Class names.** `Forge1201Transformer.mapClass`: a row of `forge-curated-renames.tsv`, `forge-event-renames.tsv` (generated) or `forge-fml-renames.tsv` wins; otherwise the package
  prefix moves (`net/minecraftforge/` to `net/neoforged/neoforge/`, `fml`, `eventbus` to `bus`, ...). A class that moved by prefix and does not exist in 1.21.1 is exactly the
  `TextureStitchEvent` failure, so the audit resolves every Forge event the same way and looks the result up in NeoForge.
* **Facades.** A class in `src/main/java/legacyconnector/v1_20_1/net/minecraftforge/...` replaces the Forge class (overlays, `TickEvent`, `LivingHurtEvent`, `NetworkEvent`, ...); the old event is
  posted from the new one in `Forge1201Events` (common) and `Forge1201Client` (client).
* **Members.** `forge-members.tsv` renames a member (any descriptor); `forge-call-rewrites.tsv` redirects a call whose owner/name/descriptor 1.21.1 lacks to a static helper
  (`owner.name(desc)ret<TAB>helper`; `TailClient.name` = `ForgeApiTailClient1201`, the client part so a dedicated server never loads client classes; the helper takes the receiver
  typed as the owner of the call first, hence one overload per owner). Mod events get `ICancellableEvent` from their `@Cancelable` annotation.
* **Abstract events.** NeoForge refuses a listener on an abstract event; `neoforge-abstract-events.tsv` (generated by `EventTables1201Tool`) fans such a listener out to the concrete events.
* `loader/.../tools/EventTables1201Tool` reports unmapped Forge events when given the Forge jar (`./gradlew eventTables1201 -PeventJars=... -PforgeJar=...`); this audit repeated its check
  without Gradle (class files parsed directly) and added the member level the tool does not do: for each event with a counterpart, every public method (name, parameter and return
  types by simple name) of the Forge class against the NeoForge class and its superclasses, the event bus (mod/game), and `ICancellableEvent` against `@Cancelable`.

## Open items needing design

1. **`RenderLevelStageEvent.getPoseStack()`: semantics, not a signature.** In 1.20.1 the pose stack of every stage carried the camera rotation (`LevelRenderer.renderLevel` applied it to the
   stack before the event); in 1.21.1 `getPoseStack()` is an identity stack and the rotation is `getModelViewMatrix()`. A mod that renders world-space geometry in a stage
   (selection boxes, outlines, line renderers) translates by the camera position on the stack it gets and now draws rotated against the view. Proposal: a call rewrite row
   `RenderLevelStageEvent.getPoseStack()` to a helper that returns, per event instance (cache the last event), a fresh `PoseStack` whose last pose is `getModelViewMatrix()` (normal =
   inverse transpose of its upper 3x3), never the shared stack (vanilla keeps using that one after the event). Not implemented: only a client with a mod that renders in a stage can show
   whether the extra matrix is right (the projection matrix also changed place: it is a separate argument of the event in both versions). `Stage` itself has every 1.20.1 constant.
2. **`RegisterTextureAtlasSpriteLoadersEvent`** (custom `ITextureAtlasSpriteLoader`s for atlas entries) has no 1.21.1 class: texture loading moved to data-driven `SpriteSource`s. Proposal: a
   facade event and `ITextureAtlasSpriteLoader` interface in the shim so the mod loads, registrations recorded and logged once, atlas sprites that name such a loader loaded as plain sprites; only
   mods that ship animated or multi-part sprites through a custom loader lose anything.
3. **Constructors.** Mods that post these events themselves (rare: `RenderGuiEvent`, `RenderLevelStageEvent`, `ScreenEvent.MouseScrolled`, `InputEvent.MouseScrollingEvent`,
   `ViewportEvent.ComputeCameraAngles`, `ModelEvent.ModifyBakingResult`, `CustomizeGuiOverlayEvent`, `RenderHighlightEvent`) construct them with 1.20.1 argument lists; 1.21.1 takes a `DeltaTracker` instead
   of a float, two scroll axes, ... Proposal: `<init>` rewrite rows to static factories, only when a mod needs one.
4. **Custom overlays.** `RenderGuiOverlayEvent` is posted for the layers `VanillaGuiOverlay.byLayer` knows; overlays a mod registers itself through `RegisterGuiOverlaysEvent` render as GUI layers
   but do not get their own Pre/Post. Proposal: wrap each registered overlay in a layer that posts the pair around the mod's `IGuiOverlay` (the facade already knows the registration).

## Model locations (`ModelResourceLocation`)

In Forge 1.20.1 `ModelResourceLocation extends ResourceLocation` (path plus variant); in 1.21.1 it is an unrelated record (`id`, `variant`). Translated code keeps the 1.20.1 shape: the loader maps
the class name to `LegacyModelResourceLocation` (a `ResourceLocation` subclass with the variant; the layer's access transformer opens `ResourceLocation`: `public-f` and the `(String, String)`
constructor), so a model location passed as a `ResourceLocation`, stored in generic containers or cast back needs no conversion. Conversion happens only where the legacy code calls into the modern
game (rows in `mc-calls.tsv`, `mc-fields.tsv`, `forge-call-rewrites.tsv`, helpers in `ModelLocationCompat`):

| 1.21.1 member | what legacy code gets or passes |
|---|---|
| `ModelEvent.ModifyBakingResult/BakingCompleted.getModels()` | a live `Map<ResourceLocation, BakedModel>` view (`LegacyModelMap`): iteration yields `LegacyModelResourceLocation` keys (plain `ResourceLocation` for standalone models), `get`/`containsKey`/`remove` take legacy keys, plain ids or records, writes go through |
| `ModelEvent.RegisterAdditional.register(ResourceLocation)` | plain id -> `ModelResourceLocation.standalone(id)`; a legacy location -> `(id, variant)` |
| `ModelManager.getModel(ModelResourceLocation)` / Forge's `getModel(ResourceLocation)` | converted; a plain id looks up the standalone model, then the `inventory` variant |
| `BlockModelShaper.stateToModelLocation` (both overloads) | returns `LegacyModelResourceLocation` |
| `ItemModelShaper.register(Item, ModelResourceLocation)` | converted |
| `ItemRenderer.TRIDENT_IN_HAND_MODEL`, `SPYGLASS_IN_HAND_MODEL`, `ModelBakery.MISSING_MODEL_LOCATION` (now `MISSING_MODEL_VARIANT`) | field rows return the legacy class |

Key mapping: legacy key with a variant `ns:path#variant` is the record `(ns:path, variant)`; a plain `ResourceLocation` is the record `(id, "standalone")` (1.21.1 registers additional models as
standalone; in 1.20.1 they were plain keys in the same map). Not routed (no mod in the ATM 9 set uses them; add a row when one does): `ItemModelShaper.shapes`,
`RegistryAwareItemModelShaper.getLocation`, `BakedModelRenderable.of(ModelResourceLocation)`, `ModelBaker.getTopLevelModel`.
