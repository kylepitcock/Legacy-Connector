# Mod dimensions

Back to [Home](Home.md); see also [World generation](World-Generation.md).

A dimension a legacy mod registers with `DimensionManager.registerDimension` becomes the modern dimension
`legacyconnector:dim_<id>`. Its chunk generator (`LegacyChunkGenerator`) runs the mod's `WorldProvider.createChunkGenerator()`:
terrain comes from `provideChunk` (block/metadata arrays), trees, structures and ores from `populate`. Biomes come from the
provider's own `WorldChunkManager` layers (`LegacyBiomeSource`), and `World.provider` is an instance of the mod's provider class.
After `populate` the mods' IWorldGenerators run, as `Chunk.populateChunk` ran them; hooks that coremods patched around that pass
run first (`LegacyChunkGenerator.addPopulationInterceptor`, a cancelled hook skips the pass): DragonAPI's `ChunkPopulationEvent`,
from which ChromatiCraft places its dimension structures. Those are computed whole at startup into per-chunk buffers (about
100 MB in a heap summary of an ATM10 pack) and each chunk's part is placed and dropped when the chunk populates, so the buffers
of chunks nobody generated stay, as in 1.7.10.
`ServerConfigurationManager.transferPlayerToDimension` and `Teleporter` work as in 1.7.10. Verified with Twilight Forest's
terrain, portal and fog, and Galacticraft's planets (per-planet gravity, silent space). A dimension takes its fog colour, cloud height, sky/cloud/weather renderers and flat-world horizon from its legacy `WorldProvider`; legacy sky renderers that draw with unsupported GL fall back to the vanilla sky.
Dimensions registered while the server runs get the same kind of level on first use (`worldServerForDimension`,
`DimensionManager.initDimension`, teleports), with a generic dimension type with or without a sky, since dimension types
cannot be added to a running server. Verified with Mystcraft's instability profiling dimension and a dimension registered at
runtime with Twilight Forest's provider; Mystcraft ages and Galacticraft space stations take the same path but are not
verified yet.

A pack may mix 1.7.10 and 1.12.2 mods. A library shipped for both versions (CodeChickenLib) or an API shaded by mods of both
keeps one copy per version: the 1.12.2 jars' copy of every package that 1.7.10 jars also define is relocated, so each version's
mods link to their own, and `Loader.isModLoaded` does not report a mod of the other version.

## Beta 1.7.3 ShockAhPI dimensions

Beta uses the original `DimensionBase` registrations through a separate native adapter. A custom registration becomes
an owner-scoped realm key, `b173_<owner>:dimension_<number>`, with its own dimension type and biome resources. The
registration number selects the native level; the original provider's `id` is preserved even when its initialization
assigns a different value. Vanilla Overworld and Nether registrations retain their existing levels. This does not
change the `legacyconnector:dim_<id>` mapping used by the later-version adapters above.

`ChunkGeneratorB173` binds the original provider to the live world and creates its original `ChunkSource` once.
Terrain comes from `getChunk`: the Beta chunk retains its 32,768-byte array while the provider fills it, with unsigned
block IDs, metadata, local heightmaps and y=0..127. Shared Beta noise, climate, cave and lake APIs run the original
algorithms. `BiomeSourceB173` queries the provider's original biome source and resolves custom biome identities to
registered native holders. Before live levels exist, it uses the supplied registered biome holders.

During native biome decoration, `decorate` runs against the generation region with scoped legacy world/player context.
The owning mod, chunk source and biome manager serialize their mutable state. Native biome modifiers can add features
after original population; the adapter adds no modern terrain, surface or carver pass. Missing neighbour terrain comes
from bounded snapshots generated by an independent original source, preserving the active populator's random stream
and biome scratch arrays. Pending deferred writes override these snapshots. Distant writes and tile stand-ins use the
shared deferred-write bridge; neither fallback reads nor height queries request full native chunks. Spawn collision
checks remain strict about available native terrain.

Completed Beta population writes and final tile NBT are persisted in per-level SavedData until normal native chunk
loading accepts them. Replay retains write order, hydrates pending overlays before generation, and acknowledges an
attachment only after it succeeds. Unfinished population snapshots are excluded from saves.

Shared SAPI block interception uses the first matching original handler before a write. Batched writes defer neighbour
and shape notifications while retaining client synchronization. Registered portals use native server travel plus original
distance scaling and teleporters, including keep-previous-angle placement. Client distortion and configured portal sounds
use the same portal lifecycle; player placement refreshes preserve existing inventory state.

**Native verification:** unchanged Aether 1.02 activates its portal through real water-bucket input and completes
walking round trips on dedicated servers and integrated single-player, retaining original landing placement and all eight
equipped accessories. Integrated save/reopen preserves the realm and equipment. Dedicated full-process restarts preserve
custom biome identities and complete block/metadata digests of two island chunks. A separate restart preserves 26,476
pending writes and two unloaded dungeon-chest inventories; normal native chunk loading materializes both exact loot
snapshots. Original game hooks also return a falling player to the Overworld.

Native gameplay checks additionally cover original tool mining/drop/wear behavior, freezer/enchanter processing, a full
6,000-tick incubator hatch and Moa feeding, passive interactions/relog, native weapon-triggered lightning/flash, and
two-client poison application, victim-only timed damage/recovery and isolation during attacker realm travel. Life Shard
use establishes native health/capacity 22 while preserving foreign health attributes; server and owner client agree after
native death/Respawn and full-process rejoin. Two real clients also pass owner and remote presentation/inventory checks.
Neptune equipment changes actual submerged movement. See [verified Beta gameplay](Legacy-b1.7.3.md#verified-native-gameplay-and-current-limits) for scope.

Incubator post-hatch empty inventory/progress0 survives a full-process restart in live and stored chunk NBT, with the
same hatched Moa UUID and no duplicate after another 6,000 ticks. Both parachutes pass native safe-fall checks. Real
MiniCloud air-click input creates two original projectiles with native ticking and client tracking/rendering; combat and
full-lifetime acceptance remain separate.

The custom biome's eight passive and three hostile entries participate in the Beta scheduler. Fresh-world native natural
spawn finalization/joins and subsequent original ticking are verified for Zephyr, Aerwhale, Cockatrice and Aechor Plant;
native caps remain enforced, and ordinary Overworld spawn ownership is unchanged. This is bounded admission/ticking
proof, not complete AI coverage for all eleven entries.

A naturally generated Bronze Slider survives a full-process restart in the deferred entity queue with identical complete
NBT, UUID, original/native type, dungeon home and name, while its target has never reached native FULL. Native chunk
loading then materializes exactly one matching boss and acknowledges the entry. The same 500-HP boss passes real native
pickaxe combat in Survival, original charging/player damage and critical visuals, death, doorway/block unlocking,
trapdoors and actual drop pickup. Native armor and declared Resistance protect the test actor; original boss state is
not changed by the fixture. The actual key unlocks the generated chest, its original screen renders, and real mouse
transactions collect all three generated items. A full client/server restart preserves the empty unlocked chest,
doorway, defeated-boss outcome and exact collected native stacks. Silver/Gold encounters and other remaining gameplay
checks are separate; these results do not establish complete Aether gameplay or universal ShockAhPI compatibility.

### NeoForge integration boundaries

Beta custom spawning uses `ModifyCustomSpawnersEvent` and the native `CustomSpawner` lane, with the Beta entry first and
existing spawners retained. Narrow mixins still capture native eligible chunks/accounting, intercept all block writes
before storage for SAPI, and supply provider celestial time: placement events cover fewer write paths, while level
extensions and sleep-time events do not expose a celestial-fraction override. Native chunk generators, biome resources,
level events and deferred-write SavedData handle the other dimension lifecycle work. The
[Beta API/mixin matrix](Legacy-b1.7.3.md#native-apis-and-narrow-mixin-gaps) records the precise remaining gaps, including
container rendering and inventory input; an available event is preferred whenever it preserves the complete operation.
