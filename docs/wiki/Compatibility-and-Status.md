## Known compatibility issues

Found by loading a ~140-mod 1.7.10 test pack (`test-mods/`) together. Everything not listed here loaded in the last
full run; "loads" does not mean every feature was played through.

| Mod / combination | Issue | What to do |
|---|---|---|
| RotaryCraft (with DragonAPI) and Forestry 4.2.16 | DragonAPI's wood list asks Forestry for blocks named `planks2` and `slabs1`-`slabs4`, which Forestry 4.2.16 does not register (it has `planks` and `slabs`); the list then holds a null block and RotaryCraft is disabled at post-init. The same names broke Binnie's pre14. DragonAPI and ReactorCraft load. | Use a Forestry/DragonAPI pair built for each other (no matching 1.7.10 Forestry build was found on Modrinth). |
| Binnie's Mods 2.0-pre14 with Forestry 4.2.16 | Binnie was built for an older Forestry API (`getProducts`, `getLogStacks`, `planks2` do not exist in 4.2.16); ExtraBees, Botany, BinnieCore and ExtraTrees fail, and anything that runs their recipes (ThermalExpansion) with them. | Use Binnie's Mods 2.0.22.7 (loads); Binnie Patcher is then not needed. |
| Witchery + the Reika mods | Witchery's potions default to ids 32-75; RotaryCraft's freeze potion is 35, ChromatiCraft's potions 36-42 and ReactorCraft's radiation 140, so DragonAPI refuses to start. | Move Witchery's potions: in `config/witchery.cfg` add 32 to every id in the `potions` block and to `PotionStartID` (64-107; keep ids below 128, 1.7.10 stores potion ids as a byte). Legacy Connector saves effects by name, so worlds keep their effects. |
| ProjectRed Expansion + Runic Dungeons | Both use enchantment id 80. 1.7.10 crashed; here one enchantment is moved to a free id and a warning is logged. | Change an id in the mods' configs to keep ids stable. |
| Mystcraft + NetherOres | NetherOres swaps the vanilla quartz ore block through CoFH registry reflection. Works, because replaced vanilla blocks keep the vanilla identity. | None. |
| Mods that patch Minecraft's own classes with coremods | The patches cannot run on the shim classes. Only DragonAPI's crafting-list and smelting hooks (`CoremodHooks`) and Fisk's Heroes' hooks (`compat.fiskheroes`: movement, model poses, Moon/Quantum Realm and gravity-power gravity, healing factor heal rate, stealth against mobs, speedster slow motion as the server tick rate, suit footsteps, size/scale of players, camera roll and shake, first-person suit arms, left-click locks) are provided; other such patches do nothing. Not wired for Fisk's Heroes: the off-hand item in first person, night-vision overrides, intangible light tweaks, inventory preview scale; on a dedicated server heroes fly only with `allow-flight=true` (as in 1.7.10). | Report the mod. |
| The Betweenlands (1.7.10 1.0.6 and 1.12.2 3.9.6) | Both load and their dimension generates and renders. Its own mob spawner (`MobSpawnHandler`) produces no mobs yet, and some item models and sounds are missing (the sound ambience handler fails on a missing sound accessor). The 1.7.10 version replaces the title screen with its own; the shim's `GuiMainMenu` provides vanilla's buttons for it. | Use spawn eggs for now. |
| Morph 0.9.3 (1.7.10) with iChunUtil | Morphing into mobs and the morphed size work. The kill and morph-down animations and the morphed model's placement are still being fixed (#153). | None yet. |
| Thermal Expansion / Thermal Dynamics (1.7.10) | Machines and block items in the inventory show their base model (the per-machine item renderer is not reproduced); ducts do not draw their connections yet. | None yet. |
| Railcraft and EnderIO anvils | `ContainerRepair` is implemented with the vanilla field names and rules; not yet checked in game. | Test in game. |
| HBM's pylons/substations, RFTools screens, Thermal Expansion tanks and caches, Runic Dungeons portal | Fail in the automated block self test, which uses a fake player and no tile state; not confirmed in real play. | Test in game. |
| Decocraft | Loads through a stand-in for the JDK-internal PNG reader; models not checked in game. | Test in game. |
| Tinkers' Construct and other mods whose `getSubItems` reads client-only icon arrays | Subtype discovery registers icons against a detached register; blocks whose arrays still stay empty get metadata 0 only until used. | None. |
| Villager professions, trades and village components (`VillagerRegistry`) | Modded professions with skins and trade handlers appear on some new unemployed villagers (they have no job site unless `villagers.jobSites` maps one). Village creation handlers (Witchery's shops, walls, towers; AgriCraft's greenhouses) build their components inside modern villages, planned beside the modern streets and facing them (1.7.10's `getNextComponentNN/PP`); layouts that continue from a mod's own paths get the next building as 1.7.10 chose it, and plans are kept per village so every chunk builds the same components. The vanilla piece factories mods call (`House1.func_74898_a` ...) build the modern village building of the same use, turned to the path. Modded villagers have no job site unless `villagers.jobSites` maps their profession to a block (1.7.10 professions declare none; see [Configuration](Configuration.md)). | Fixed for components; job sites only by config. |
| `/locate structure` | Vanilla structures are found in legacy biomes (they join the vanilla biome tags). Structures drawn by legacy generators are found with `/locate structure <mod>:legacy/<name>` (the generator's name, lower case; listed by tab completion), at any distance, from an index of the builds recorded as chunks generate. Terrain that has not generated yet cannot be searched: legacy generators decide while building and keep state that a dry run would corrupt (see [World generation](World-Generation.md)). | Partly fixed. |
| JourneyMap / Custom Main Menu / Inventory Tweaks (1.7.10 versions) | Loaded like any other legacy mod. Custom Main Menu replaces the title screen (`GuiOpenEvent`/`GuiScreenEvent` are bridged; its panorama, logo and splash draw, buttons are being verified). The other two are not verified. | Report what you see. |
| FastCraft, Hodgepodge, NEID and other engine/launcher patches | Intentionally not loaded (see [Bridges](Bridges.md)). | Use their modern equivalents. |

## What happens to a mod

After launching, read **`logs/legacyconnector-report.txt`**. For every legacy jar it lists the detected version and mod
ids, references that could not be linked, and which legacy APIs were synthesized (they link but do nothing yet).
At runtime, `LegacyConnector/Stubs` log lines show which synthesized APIs are actually called.

## What the compatibility ratings mean

The [compatibility site](https://kylepitcock.github.io/Legacy-Connector/) rates every mod with one of these (renamed on 2026-11-06 to plain words; the data keys did not change, so old links and reports still work):

| Rating (was) | Meaning |
|---|---|
| **Fully playable** (Near-perfect) | You can play it in survival; the maintainer played it and only small problems are known. |
| **Mostly playable** (Playable) | Played in survival and most of it works; some mechanics or abilities are broken or were not tried. |
| **Basics work** (Works) | Its blocks, items and mobs showed up and behaved in a test; deeper mechanics were not checked. |
| **Partly working** (Partial) | It loads and part of it is usable, but some features are known to be broken. |
| **Starts, untested** (Loads) | It starts without errors and passes the startup check; nobody has played it yet. |
| **Does not start** (Fails to load) | The game starts but the mod is disabled because it failed while loading. |
| **Crashes the game** (Crashes) | Using it takes the whole game down. |
| **Not tested** (Untested) | No result yet. |

**1.20.1 on the site (alpha).** The site has a 1.20.1 tab since 2026-11-08, with an offline link check (`tools/compat/probe.py --mc 1.20.1`, which runs `./gradlew gap1201 -Pgap.translate=true`): the jar is remapped in place (SRG to Mojang, Forge to NeoForge, the Minecraft 1.20.1 to 1.21.1 migration, the Forge facades) and every reference is resolved against Minecraft 1.21.1, NeoForge and the other jars of the run. "Ready to test" there means "links against 1.21.1 plus the facades", nothing more; a mod with unresolved references can still start, because the code behind them may never run. A server start that registers a mod's content is a higher tier (a `client` entry: Another Furniture 3.0.4 registers 174 blocks, 159 items, 1 entity and 4 block entity types). Libraries with a native 1.21.1 build of the same mod id (Architectury, Curios, GeckoLib, Patchouli, Cloth Config, Resourceful Lib/Config, Puzzles Lib, Citadel, Jade...) are counted as "Not needed": install the 1.21.1 build and the 1.20.1 jar is skipped; the loader's log names the build to install when a mod needs one that is missing. First run (2026-11-07, Connector 0.4.4, 84 jars: 60 corpus jars plus 24 libraries and content mods): 6 ready to test, 62 missing game features, 7 needing another mod, 9 libraries replaced by their native build.

## Per-version notes (moved from the README on 2026-11-14)

The README keeps one sentence per version; the longer notes it used to carry are here. Counts are those of the README of release 0.4.14 and are not updated automatically.

### README status paragraph

**Status: beta (0.4.x).** The point is mods that **only exist on these old versions** and never got a 1.21.1 port.
1.7.10 is in beta: Thaumcraft 4, Witchery, HBM's Nuclear Tech, the Reika mods (RotaryCraft, ReactorCraft, ChromatiCraft),
OreSpawn, Fisk's Superheroes, Morph, and Galacticraft with its addons (per-planet gravity, silent space) run with their blocks, items,
entities, recipes, GUIs, world generation, and dimensions, and large tech packs like GT New Horizons load most of their mods.
1.12.2 is in beta: Atum 2, The Midnight, The Betweenlands, Scape and Run: Parasites, and Abyssalcraft load and play in a real
client with their own models, GUIs, mobs, dimensions, and world generation.
1.20.1 (Forge) is in alpha: mods are remapped in place onto NeoForge 1.21.1. Terramity (with its GeckoLib bosses) runs in a real client and Another Furniture registers its content; Palladium and its addon packs (Alien Evolution) have their own adapters, including KubeJS 7 script compatibility; most other 1.20.1 mods still have unresolved references. It is on by default and does nothing unless a Forge 1.20.1 jar is installed.
1.6.4 is in beta (2026-11-08); 1.5.2 and 1.4.7 are new in 0.4 and in alpha: RedPower 2, BuildCraft, ComputerCraft, and Applied Energistics (1.4.7), Twilight Forest and
Applied Energistics 1 (1.5.2), Tinkers' Construct, Mo' Creatures, and Goblins! (1.6.4), and many more run in a real client. Some
features are still missing (see [Known compatibility issues](Compatibility-and-Status.md#known-compatibility-issues)); back up your worlds before trying a new
mod set.
