# Compatibility and status

Per-mod results are on the [compatibility site](https://kylepitcock.github.io/Legacy-Connector/). Back to [Home](Home.md).

| Legacy version | Status |
|---|---|
| 1.7.10 | **Beta.** Iron Chest, Twilight Forest, Thaumcraft, HBM, RFTools, Thermal Expansion and others work in game; Galacticraft with its addons runs with per-planet gravity. In-game self tests (every block placed and used, every item used, every mob spawned) of the GT New Horizons pack and a 130-jar 1.7.10 list rate 166 mods as working and 57 as partly working; 20 fail during loading (see the [compatibility list](https://kylepitcock.github.io/Legacy-Connector/)). Mod biomes, world types and dimensions generate; mod entities spawn, tick, fight and save; entity rendering (including the player renderer), armour and held items, dimension fog/sky and Twilight Forest's portal are bridged, though not verified in game for every mod. All synthesized API classes pass JVM verification. |
| 1.12.2 | **Alpha (issue #64).** Content mods load and play in a real client: blocks, items, mobs with their own renderers and AI, GUIs, world generation, loot, natural spawning, advancements and Forge events. Implemented: the FML lifecycle, registry events (blocks, items, potions, enchantments, sounds, biomes, entities, recipes, villager professions, custom registries made with `RegistryBuilder`), items with subtypes, blocks and block states (one `meta` property mapped through `getStateFromMeta`/`getMetaFromState`), tile entities with client sync, capabilities (items, fluids, energy), networking channels, recipes (code recipes become data pack recipes), ore dictionary, tools/armor, fluid data model, `@ObjectHolder`, `@SidedProxy`, `@EventBusSubscriber`, coremod plugins and vanilla constants (`Blocks`, `Items`, ...), the server lifecycle events (`FMLServerStartingEvent` and the others) and server commands (`ICommand`/`CommandBase` commands become modern commands), and the registries mods add to at load time (criteria triggers, loot functions and conditions, data serializers, villager trades, Forge's biome lists, grass seeds, enderman-carriable blocks). Mod blockstates, item models (`ModelLoader`) and model/texture names renamed after 1.12 are translated,. The client has run with Botania, Blood Magic, Mekanism, EnderIO, Immersive Engineering, Tinkers' Construct, Quark, Biomes O' Plenty, Vampirism, the Aether and Scape and Run: Parasites; some models still show as missing. Server tests: of 32 big jars (EnderIO, Mekanism, Thermal, BuildCraft, AE2, Botania, Blood Magic, Tinkers, Forestry, Thaumcraft, Twilight Forest, BoP, ...) 1 of 50 mod ids still fails (BuildCraft Silicon) and about 2060 blocks, 3480 items and 3670 recipes register (`@Config` classes are filled from their config files; vanilla items with metadata map to their flattened modern items); of 39 more jars (Roots, Vampirism, Totemic, RFTools, Pam's HarvestCraft, The Betweenlands, Ice and Fire, TechReborn, ...) 16 of 42 mod ids fail, some from missing dependency jars. In the larger 116-jar server test (2026-10-30) about 5,050 blocks and 10,170 items register, 11 mods fail (10 of them because a dependency jar is missing), and the self test places and right-clicks every block and uses every item without errors; per-mod ratings are on the compatibility site. Every legacy API the 1.12.2 test mods use has an implementation, except internals with no 1.21.1 counterpart. Blockstates in Forge's v1 format (defaults, per-variant textures), code-defined state mappers, OBJ models and Forge's model loaders are translated. Also implemented: entities with their AI, renderers and models (vanilla mob classes included), containers and GUIs, Forge fluids that flow, world generation (IWorldGenerator, biome layers, terrain events, structures), loot tables, natural spawning, advancements, the scoreboard and the Forge client events. Still missing: rail physics for mod minecarts and riding mod horses, and some vanilla renderers (boats, horses). Results per mod are on the compatibility site. Performance, bug-fix and mixin-loader mods (FoamFix, BetterFPS, VanillaFix, ...) are skipped. |
| 1.16.5 | Planned. |
| 1.2.5 | Planned (after 1.16.5). |
| 1.20.1 (Forge + Fabric via Sinytra Connector) | Planned. |

Not supported (and likely never fully): coremod transformers and mixins that patch legacy Minecraft code itself,
LaunchWrapper tweakers. They are reported, and the rest of the mod still loads. Where a coremod only exists to change
engine behaviour that has a modern equivalent, the layer bridges the behaviour instead (Galacticraft's gravity and
silent space are applied per dimension, see *Dimension physics* in [Bridges](Bridges.md)).

## Known compatibility issues

Found by loading a ~140-mod 1.7.10 test pack (`test-mods/`) together. Everything not listed here loaded in the last
full run; "loads" does not mean every feature was played through.

| Mod / combination | Issue | What to do |
|---|---|---|
| RotaryCraft (with DragonAPI) and Forestry 4.2.16 | DragonAPI's wood list asks Forestry for blocks named `planks2` and `slabs1`-`slabs4`, which Forestry 4.2.16 does not register (it has `planks` and `slabs`); the list then holds a null block and RotaryCraft is disabled at post-init. The same names broke Binnie's pre14. DragonAPI and ReactorCraft load. | Use a Forestry/DragonAPI pair built for each other (no matching 1.7.10 Forestry build was found on Modrinth). |
| Binnie's Mods 2.0-pre14 with Forestry 4.2.16 | Binnie was built for an older Forestry API (`getProducts`, `getLogStacks`, `planks2` do not exist in 4.2.16); ExtraBees, Botany, BinnieCore and ExtraTrees fail, and anything that runs their recipes (ThermalExpansion) with them. | Use Binnie's Mods 2.0.22.7 (loads); Binnie Patcher is then not needed. |
| Witchery + RotaryCraft | Both default to potion id 35; DragonAPI refuses to start. | Change `Freeze Potion ID` in `config/Reika/RotaryCraft.cfg` (or Witchery's id). |
| ProjectRed Expansion + Runic Dungeons | Both use enchantment id 80. 1.7.10 crashed; here one enchantment is moved to a free id and a warning is logged. | Change an id in the mods' configs to keep ids stable. |
| Mystcraft + NetherOres | NetherOres swaps the vanilla quartz ore block through CoFH registry reflection. Works, because replaced vanilla blocks keep the vanilla identity. | None. |
| Mods that patch Minecraft's own classes with coremods | The patches cannot run on the shim classes. Only DragonAPI's crafting-list and smelting hooks are provided (`CoremodHooks`); other such patches do nothing. | Report the mod. |
| Railcraft and EnderIO anvils | `ContainerRepair` is implemented with the vanilla field names and rules; not yet checked in game. | Test in game. |
| HBM's pylons/substations, RFTools screens, Thermal Expansion tanks and caches, Runic Dungeons portal | Fail in the automated block self test, which uses a fake player and no tile state; not confirmed in real play. | Test in game. |
| Decocraft | Loads through a stand-in for the JDK-internal PNG reader; models not checked in game. | Test in game. |
| Tinkers' Construct and other mods whose `getSubItems` reads client-only icon arrays | Subtype discovery registers icons against a detached register; blocks whose arrays still stay empty get metadata 0 only until used. | None. |
| Villager professions, trades and village components (`VillagerRegistry`) | Modded professions with skins and trade handlers appear on some new unemployed villagers (they have no job site). Village creation handlers (Witchery's shops, walls, towers; AgriCraft's greenhouses) build their components inside modern villages, planned beside the modern streets and facing them (1.7.10's `getNextComponentNN/PP`); layouts that continue from a mod's own paths get the next building as 1.7.10 chose it, and plans are kept per village so every chunk builds the same components. The vanilla piece factories mods call (`House1.func_74898_a` ...) build the modern village building of the same use, turned to the path. Modded villagers have no job site. | Fixed for components; job sites not fixed. |
| Achievement pages | Achievement pages are recorded but not shown (1.21 has advancements); achievements are earned and shown as toasts. Mod potions in the brewing stand and mod fishing catches work (see the bridges table). | Not fixed. |
| `/locate structure` | Vanilla structures are found in legacy biomes (they join the vanilla biome tags). Structures drawn by legacy generators are found with `/locate structure legacyconnector:<name>` (the generator's name, lower case), among visited chunks only. | Not fixed. |
| Tinkers' Construct materials on modern Tinkers | Not bridged: the real modern Tinkers' Construct exists only for 1.20.1, not NeoForge 1.21.1 (planned with the 1.20.1 target). | None. |
| JourneyMap / Custom Main Menu / Inventory Tweaks (1.7.10 versions) | Loaded like any other legacy mod. Custom Main Menu replaces the title screen (`GuiOpenEvent`/`GuiScreenEvent` are bridged; its panorama, logo and splash draw, buttons are being verified). The other two are not verified. | Report what you see. |
| FastCraft, Hodgepodge, NEID and other engine/launcher patches | Intentionally not loaded (see [Bridges](Bridges.md)). | Use their modern equivalents. |

## What happens to a mod

After launching, read **`logs/legacyconnector-report.txt`**. For every legacy jar it lists the detected version and mod
ids, references that could not be linked, and which legacy APIs were synthesized (they link but do nothing yet).
At runtime, `LegacyConnector/Stubs` log lines show which synthesized APIs are actually called.
